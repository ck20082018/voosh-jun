# Инженерные задания карты

Задача `logic/map-directions`: согласованное пользователем расширение за пределы трёх заданий исходного [MVP](MVP.md), с технической проверкой по M6. Учебное утверждение человеком и пилот M7 не заменяются автотестами.

Карта содержит 21 миссию: пять прежних производственных уровней, выбор инструмента и 15 новых упражнений. В каждом из пяти новых направлений первое задание доступно сразу, последующие требуют прохождения предыдущего. Выбор инструмента открывается после «Точность решает». Упражнения не требуют XP для входа.

| Направление | Задания | Что проверяет модель |
| --- | --- | --- |
| Механическая обработка | Выбор подходящего инструмента | Соответствие станка и инструмента продольному точению |
| Конструирование | Редуктор по чертежу; Ускоряющая передача; Согласовать модуль | Выбор двух колёс из каталога, межосевое расстояние `m × (z₁ + z₂) / 2`, скорость `n₁ × z₁ / z₂` |
| Процессы | Маршрут втулки; Маршрут с плоскостью; Чистая поставка | Полнота и уникальность операций, предшествование, соответствие поста |
| Метрология | Читаем нониус; За пределами допуска; Граница допуска | Показание штангенциркуля с нониусом 0,1 мм, годность по включительному диапазону |
| Автоматизация | Первый автомат; Нет заготовки; Защитный кожух | Исполнение программы при разных сигналах датчиков, безопасная остановка, порядок закрепления/обработки/разжима/выдачи |
| Логистика | Две партии; Очередь без простоя; Сменный заказ | Расписание двух последовательных станков, отсутствие наложения на каждом, срок завершения всех партий |

Модели намеренно учебные. Сборка — пара внешних цилиндрических шестерён с одинаковым модулем, без расчёта прочности и зазоров. Измерение — чтение уже установленного инструмента, без случайной погрешности и ручного перемещения губок. Маршрут проверяет технологическую карту, а не двигает предмет по сцене цеха. Автомат исполняет линейные команды и условные остановки по двум неизменным входным датчикам; динамические отказы, циклы и язык ПЛК не реализованы. В расписании два станка, одинаковая очередь на обоих, неограниченный промежуточный буфер, нет переналадки и транспортных задержек. Проверяются все подходящие решения, а не совпадение с единственным эталоном.

## Контракт логики и интерфейса

`MissionSpec` — объединение двух видов заданий: прежний `build(): Level` либо `exercise: Exercise`. Например, `exercise: { kind: 'measurement', whole: 12, tick: 7, min: 12.6, max: 12.8 }`. Редактор и компилятор по-прежнему работают только с производственным `Level` v4. ID прежних миссий и сохранений не меняются; ID бывших заглушек используются для соответствующих играбельных упражнений.

Чистые модели находятся в `src/platform/exercises.ts`, содержание — в `exerciseMissions.ts`. `ExerciseSession` владеет попыткой, повторно проверяет отправку и возвращает копии результатов; интерфейс не может завершить попытку сменой флага. У производственной и инженерной попытки общий отчёт `AttemptReport`, который использует платформа для результата и сохранения профиля. Дополнительные критерии `AttemptSummary.criteria` заменяют производственные подписи только для упражнений, в сумме дают 500 баллов. Формула точности, самостоятельности и времени сохранена. Производственные достижения «Первая стружка» и «Многоступенчатый» не выдаются за лабораторные упражнения.

Общие файлы, изменяемые исполнителем этой задачи: `src/App.tsx`, `src/screens/Hub.tsx`, `src/screens/MissionMap.tsx`, новые `ExerciseScreen.tsx` и `ExerciseDiagram.tsx`, интеграционные тесты и документация. Оформление новых упражнений изолировано в `src/screens/exercises.css`; существующие CSS и геометрия цеха не меняются.

Состояния: заказ до старта; ввод решения; синхронная проверка; ошибка с причинами и возможностью исправить; успешное решение с переходом к общему результату; новая попытка через «Улучшить результат». Отдельного асинхронного состояния обработки нет. Каждая неудачная отправка считается одной ошибкой независимо от количества нарушенных условий. Очистка ответа не обнуляет штрафы. Во время скрытой вкладки время не идёт. Прогресс и завершённые результаты сохраняются; незавершённый ответ хранится только в текущем экране и после выхода вводится заново.

## Проверка

Автотесты `tests/exercises.test.ts` проверяют решаемость всех заданий, альтернативные решения, ошибки, повторную отправку, штрафы, границы допуска, безопасность программ, расписания, достижимость миссий и сохранение результатов. Прежние тесты производственного прохождения продолжают проверять все миссии с `build`.

Браузерная приёмка: [BROWSER_ACCEPTANCE.md](BROWSER_ACCEPTANCE.md). Для этой задачи нужны карта/хаб, все новые рабочие места, неверное решение и исправление, результат, повторная попытка, сохранение/перезагрузка, блокировка прямого URL закрытого задания. Отчёт фактически выполненной проверки добавляется в PR.

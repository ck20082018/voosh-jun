# Чертёж на листе и просмотр отдельной детали

Расширение T3 явно запрошено владельцем. Реализация в `logic/eskd-drawing-and-3d-viewer` использует T3–T5 как зависимости, не объединяет их в main и не заменяет изометрический цех. Рабочая учебная схема с инструментом сохраняется для объяснения движений; отдельная кнопка «Чертёж на листе и экспорт» открывает печатное представление. «Объёмная модель» теперь открывает настоящую вращаемую модель. В планировании «Изучить деталь» доступно для заказа и пробного результата; карточки внутри кнопок каталога остаются без вложенных кнопок.

Нормативные источники, проверенные правила и ограничения: [DRAWING_STANDARDS.md](DRAWING_STANDARDS.md). Это учебный чертёж поддерживаемой геометрии, не произвольное CAD-ядро и не полный производственный документ.

## Контракт для оформления и автора

Исходная `TurningGeometry` не меняется: мм, Z=0 со стороны патрона, +Z к свободному торцу, поля `outer0/outer1/inner0/inner1` — **радиусы**. Резьба — отдельный признак. Требования и фактический предмет передаются разными значениями; переключатель источника никогда не присваивает результат заказу.

```ts
const display: DrawingDisplay = {
  views: ['main', 'end', 'section', 'volume'],
  sheet: {
    format: 'A3', scale: 1,
    views: ['end'],
    dimensionOffsets: { 'total-length': { x: 4, y: -1 } }, // мм ЛИСТА
    detail: { z0: 56, z1: 60, scale: 2, surface: 'outer' }
  }
};
```

`Level.drawing` — необязательное расширение JSON v4 без смены существующих ID/формата геометрии. Импорт проверяет настройки; сериализация, сохранение черновика и компиляция сохраняют их. Редактор → «Настроить чертёж» → выбрать надпись → изменить x/y → закрыть просмотр → «Сохранить» или экспортировать JSON. Изменение проходит через обычный `setLevel`, историю редактора и сохранение. Смещения относятся к стабильным геометрическим ID, не к номерам операций. При изменении профиля удалённые ID просто не применяются.

`DrawingMetadata` содержит название и только известные материал/обозначение/организацию/автора. Не передавайте учебные догадки как метаданные. Название уровня допустимо использовать как название задания; отсутствие обозначения оставляет графу пустой.

`makeSheet()` — чистая функция: возвращает физический лист, проекцию главного изображения, размеры, векторные примитивы и предупреждения. `selectionOnSheet()` возвращает отдельные линии выделения. Экспортеры получают только лист. Габариты шрифта получены из встроенного статического Onest; высота прописных букв переводится в em через capHeight 0,707. Смена масштаба и авторских надписей не изменяет деталь.

`latheMeshes()` — чистая триангуляция: X мира соответствует Z предмета, Y/Z мира — радиальная плоскость. Модель центрирована только для камеры, единицы остаются мм. 192 сегмента по окружности. Нормали цилиндров/конусов аналитические; у торцов, уступов и плоскости среза отдельные вершины и нормали. На границе участков строится разность материальных колец, без двух совпадающих торцов. Для среза остаётся половина тела, открытая поверхность материала закрыта плоскими гранями; отверстия остаются пустыми. Разбиение при выделении не добавляет торцы.

`PartViewer` загружается через `React.lazy`, Three.js не входит в начальный модуль. Выбор сделан после проверки зависимостей: Phaser обслуживает существующий 2D-цех, но не решает задачу камеры и освещения отдельной 3D-детали. Three.js предоставляет BufferGeometry, WebGLRenderer и OrbitControls без второго игрового ядра. Официальные контракты: [геометрия](https://threejs.org/docs/pages/BufferGeometry.html), [камера и мышь/касания](https://threejs.org/docs/pages/OrbitControls), [dispose рендерера](https://threejs.org/docs/pages/WebGLRenderer).

Камера ортографическая, с настоящим пространственным вращением. Колесо меняет охват, а не положение глаза: он остаётся на 5R от центра вращения, перемещение центра ограничено R. Это исключает случайный въезд в тело при увеличении. Есть fit, четыре положения, reset и fullscreen с объяснением отказа браузера. Сглаживание не меняет профиль и не скругляет уступы. Детализация полигональная, математическая бесполигональность не обещается.

Один рендерер на открытый компонент. Новые данные заменяют только ресурсы модели. Отрисовка по изменению; без движения нет цикла кадров. IntersectionObserver и visibilitychange останавливают скрытую отрисовку. При закрытии снимаются наблюдатели/слушатели, освобождаются геометрии, материалы, контроллер, рендерер и контекст. Текстуры не создаются. Ошибка WebGL оставляет печатный 2D-чертёж и понятное сообщение.

Состояния UI: загрузка ленивого модуля, готовая модель/лист, создание экспорта, объяснение ошибки размещения/загрузки/WebGL, успешная загрузка файла. На первом уровне дополнительные представления открываются по действию игрока, не перекрывают обучение автоматически.

## Проверки

Фикстуры на dev-маршруте `#/drawing-fixtures`: цилиндр, три ступени, канавка/фаска, глухое и сквозное отверстия, внутренний уступ/канавка, обе настоящие резьбовые фикстуры. Они не создают новые команды изготовления.

Автотесты проверяют размеры листа/масштаб, расположение торца, отсутствие штриховки в полости, размещение надписей, сохранение смещений и независимость данных. Для сетки проверяются единичные нормали, ориентация треугольников, резкие торцы, границы в мм, дно отверстия, отсутствие перекрывающихся торцов при выделении. PDF проверяется как векторный документ со встроенным шрифтом и без изображений.

Результаты браузерной и экспортной проверки фиксируются в PR и [BROWSER_ACCEPTANCE.md](BROWSER_ACCEPTANCE.md). Бумажная печать и испытание с учениками не проводились. Для проверки чтения чертежа учителем нужен отдельный просмотр: программа не объявляет стандарты выполненными на основании одного похожего изображения.

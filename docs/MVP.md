# MVP «Учебный завод»

Статус: **уточнённый проект для согласования**. Общая концепция принята пользователем; подробные требования ниже предложены для проверки перед реализацией. Этот документ — постоянный ориентир для задач, а не отчёт о готовом продукте.

## 1. Решения и смысл MVP

Браузерная учебная мастерская для 5–7 классов. Ученик получает заказ на деталь, выбирает заготовку и оборудование, составляет последовательность операций, проверяет ожидаемую геометрию, изготавливает деталь и сдаёт её на склад. Ошибка должна вести к понятному исправлению и новой попытке.

Учитель получает три готовых задания и может создать свой вариант через существующий редактор, без программирования. MVP проверяет два результата: ученик понимает связь выбора с результатом; учитель может самостоятельно подготовить рабочее задание.

Зафиксированные уточнения пользователя:

- Сроки, даты релиза, длительность разработки и ограничения по времени прохождения не задаём. Продолжительность операций в симуляции остаётся авторским параметром модели.
- ИИ используется при разработке. Сложность реализации сама по себе не причина отказываться от полезной функции: допускаются сложные внутренние решения, если они нужны продукту и проверяемы.
- ИИ-наставника в продукте не делаем. После MVP можно отдельно рассмотреть программные подсказки, простой автоответчик, классификацию вопроса или передачу вопроса оператору. Это не обещание последующего внедрения.
- Объём MVP ограничиваем завершёнными пользовательскими сценариями и учебной пользой. Возможность писать сложный код с ИИ не означает необходимость добавить все функции в первый выпуск.

Учебная геометрия и обработка условные. Это не инструкция по работе на настоящем станке.

## 2. Границы выпуска

| Входит в MVP | Конкретная граница |
| --- | --- |
| Три доступных задания | Вводное точение с готовым планом; самостоятельная ступенчатая ось; самостоятельное фрезерование бруска |
| Изготовление | Одна физическая деталь, один выбранный станок, стол и конечный склад в каждом из трёх заданий |
| План игрока | Заготовка, станок, свободная точка карты, последовательность операций, инструмент и параметры каждой операции |
| Операции | Продольное точение последовательных участков и фрезерование верхней плоскости |
| Проверки | Выполнимость плана до изготовления; сравнение реального результата с независимыми требованиями после сдачи |
| Объяснения | Короткое вступление, подсказки по событиям, причины ошибок и сравнение результата с заказом |
| Авторский редактор | Граф, свойства, карта, каталог, требования, проверка, предпросмотр/тестовый запуск, сохранение и JSON |
| Запуск | Локальный браузерный запуск по README; статическая сборка без обязательного сервера, регистрации и API модели |
| Приёмка | Автотесты, сборка, реальный браузер и небольшой пилот с учениками/учителем |

Основная среда: компьютер или ноутбук с мышью. Для приёмки предлагаем Chrome/Chromium и Firefox при размере окна от 1280 × 720; поддержку других браузеров отмечаем только после проверки. Это предлагаемый охват, а не уже подтверждённая совместимость.

Не включаем: аккаунты, облачное хранение, кабинет учителя на сервере, электронный журнал оценок, мультиплеер, экономику, кампанию, массовое производство, реалистичную физику, новые операции, отдельную мобильную версию, генератор заданий внутри приложения, чат поддержки и ИИ-наставника. Уже реализованные группы, промежуточные склады и дополнительные примеры сохраняем; отдельными условиями выпуска их не делаем, регрессии недопустимы.

## 3. Три задания с конкретным результатом

### Задание A. «Первая деталь» — освоить изготовление

Режим: готовый план. Основа — существующий токарный пример.

- Исходная заготовка: сталь, цилиндр Ø20 × 60 мм.
- Оборудование: токарный станок и проходной резец.
- Операция: продольное точение одного участка Ø12 × 30 мм.
- Заказ: стальная деталь длиной 60 мм; необработанное плечо Ø20 × 30 мм и следующий участок Ø12 × 30 мм.
- План уже задан автором. Ученику не требуется редактировать граф или выбирать оборудование из каталога.

Путь ученика: прочитать заказ → подтвердить вступление → выбрать заготовку на столе → установить в станок → запустить обработку → дождаться завершения → выбрать деталь → передать на склад → увидеть успех.

Подсказки объясняют следующий шаг после установки и обработки. При отмене выбора цели предмет остаётся на месте. Сдача до завершения обработки и повторный запуск занятого станка не изменяют состояние. Успех показывается только после поступления правильной детали на склад, один раз за попытку.

**Приёмка A:** пройти полный путь через цех; повторить через кнопки выбора объектов; отменить выбор цели; сбросить попытку во время обработки и снова пройти. В каждой попытке остаётся одна деталь, обработка и успех не дублируются.

### Задание B. «Ступенчатая ось» — составить собственный план

Режим: план игрока. Основа — `toyAxleLevel`.

Заказ: стальная ось длиной 60 мм с профилем в указанном порядке: Ø20 × 20 мм → Ø12 × 20 мм → Ø8 × 20 мм. Схема должна однозначно показывать порядок участков: текущая модель не обрабатывает два конца оси с переворотом детали.

Каталог для задания:

| Категория | Варианты | Учебный смысл |
| --- | --- | --- |
| Заготовки | Сталь Ø20 × 60; сталь Ø10 × 60; алюминий Ø20 × 60 | Отличить физическую выполнимость от соответствия материала заказу |
| Станки | Токарный; фрезерный | Выбрать оборудование для цилиндрической детали |
| Инструменты | Проходной резец; подрезной резец; торцевая фреза | Выбрать инструмент для разрешённой операции; пояснить неподдерживаемую подрезку |
| Карта | Стол и склад закреплены; минимум две свободные разрешённые точки для станка | Разместить оборудование без совпадения с занятыми объектами |

Путь ученика: прочитать размеры → выбрать заготовку и станок → поставить станок на свободную точку → добавить операции с инструментами → проверить выполнимость → посмотреть пробный результат → при необходимости поправить план → зафиксировать → изготовить → сдать → сравнить с заказом.

Контрольные маршруты для разработчика/учителя, не автоматическая подстановка ученику:

| План или ошибка | Ожидаемая реакция |
| --- | --- |
| Сталь Ø20; точение Ø12 × 20, затем Ø8 × 20; проходной резец у обеих операций | Предпросмотр показывает заказанный профиль, изготовленная деталь засчитывается |
| Сталь Ø20; Ø12 × 10, Ø12 × 10, Ø8 × 20 | Тот же итоговый профиль засчитывается независимо от числа и ID операций |
| Алюминий Ø20 с правильными размерами операций | План выполним и может быть изготовлен; на складе ошибка материала, успеха нет |
| Сталь Ø10 с попыткой получить участок Ø12 | Физически невозможный план, изготовление блокируется с причиной |
| Сталь Ø20; сначала Ø8 × 20, затем Ø12 × 20 | Обработка выполнима; порядок участков не соответствует заказу, успеха нет |
| Сумма длин обрабатываемых участков больше 60 мм | Ошибка соответствующей операции до запуска |
| Торцевая фреза или подрезной резец для продольного точения | Объяснение несовместимости/неподдерживаемой операции, запуск блокируется |
| Смена станка или свободной точки при редактировании | Уже введённые операции сохраняются; совместимость перепроверяется |

**Приёмка B:** все строки таблицы; добавление, удаление и перестановка операций; отсутствие изменений предмета от предпросмотра; исправление выполнимого ошибочного плана после сдачи. При исправлении сохраняется черновик, предыдущая деталь и склад очищаются, новая попытка начинает с исходной заготовки.

### Задание C. «Плоская деталь» — применить принцип к другой форме

Режим: план игрока. Готовый фрезерный пример используем как основу; наличие самостоятельного задания C пока не подтверждено.

- Исходная подходящая заготовка: стальной брусок 60 × 40 × 20 мм.
- Заказ: стальной брусок 60 × 40 × 15 мм.
- Каталог: подходящий брусок; алюминиевый тех же размеров; стальной брусок 60 × 40 × 10 мм. Станки — фрезерный и токарный; инструменты — торцевая/концевая фреза и проходной резец.
- Разрешённая обработка в этом задании: фрезерование верхней плоскости. Снятие уменьшает текущую высоту, длина и ширина сохраняются.

| План или ошибка | Ожидаемая реакция |
| --- | --- |
| Фрезерный станок, подходящая фреза, снятие 5 мм со стального бруска высотой 20 мм | Итог 60 × 40 × 15 мм, успех на складе |
| Последовательное снятие 2 мм и 3 мм | Геометрически равнозначный результат засчитывается |
| Снятие 4 мм | Выполнимо, но высота 16 мм не соответствует заказу; возможна новая попытка |
| Снятие 20 мм либо суммарное снятие до нулевой/отрицательной высоты | Невозможная операция блокируется до изготовления |
| Стальной брусок высотой 10 мм | Материал нельзя нарастить; результат не удовлетворяет заказу |
| Алюминий с правильной геометрией | Изготовление выполнимо, но материал не соответствует заказу |
| Токарный станок или проходной резец для фрезерования | Причина несовместимости, запуск блокируется |

**Приёмка C:** все строки таблицы; совпадение предпросмотра и изготовленной высоты после каждой операции; исправление ошибочного результата. Сравнивать с заказом нужно реальные размеры, а не только факт окончания операций.

## 4. Поведение игрока и интерфейса

Следующие требования описывают целевое поведение MVP. Точные названия кнопок можно сохранить существующими, если смысл ясен.

| Состояние | Что видно | Что доступно и что происходит |
| --- | --- | --- |
| Чтение вступления | Заголовок, текст, схема/размеры, «Продолжить» | Подтверждение вступления; производство не обходит обязательное чтение |
| Редактирование плана | Заказ, каталог, карта, карточки операций и их параметры | Выбор и изменения, проверка, пробная обработка; незаполненный/невыполнимый план не запускается |
| Предпросмотр | Исходная деталь, ожидаемый результат, размеры | Возврат к редактированию; настоящий предмет, склад и события не меняются |
| Изготовление | Выбранные объекты, текущая операция и её порядковый номер, состояние детали | Установка, последовательная обработка, сдача; зафиксированный план нельзя менять |
| Сдача ошибочной детали | Конкретное несоответствие заказу, доступный путь исправления | Вернуться к сохранённому плану и начать новую попытку |
| Успех | Подтверждение соответствия и краткий результат | Начать заново или выйти; повторного завершения нет |
| Сброс | Возврат в исходное состояние задания | Остановка обработки, удаление предмета/складского результата, очистка плана и очереди подсказок |

Требования к объяснениям:

- Каждая ошибка указывает предмет проблемы и причину: например, «Операция 2: суммарная длина участков превышает 60 мм». Для редактируемых данных понятно, какое поле исправить.
- «План выполним» не означает «Заказ выполнен». Эти результаты показаны раздельно.
- После сдачи показываем ожидаемое и фактическое значение несоответствия: материал, форма, общие размеры либо профиль участков. Текст «неверно» без причины недостаточен.
- Подсказка помогает выбрать следующий шаг, но не подставляет правильный план. Совпадающие события не создают одновременно несколько перекрывающихся окон.
- Размеры и единицы читаемы; схема согласована с реальной моделью. Сгенерированная иллюстрация не является источником числовых требований.
- Основные действия не требуют знания редактора, JSON, типов нод или устройства ядра. Выбор объектов доступен в цехе и через подписанные кнопки.
- В основной среде окна не закрывают необходимые кнопки; поля доступны, текст не обрезается. После изменения геометрии редактора совпадают порты, концы линий и зоны взаимодействия.

Если нынешний интерфейс не даёт подробного сравнения заказа с фактом, это отдельная задача MVP, а не повод уменьшить критерий. Можно реализовать её через структурированные результаты чистой проверки и отображение в UI; контракт согласуем до изменения.

## 5. Авторский сценарий: свой вариант без кода

Учитель выполняет следующую проверочную процедуру по инструкции:

1. Открывает шаблон оси и сохраняет/экспортирует исходник перед заменой задания.
2. Меняет название и текст заказа. Для контрольного варианта задаёт сталь, общую длину 60 мм и профиль Ø20 × 30 → Ø12 × 15 → Ø8 × 15 мм.
3. В независимых требованиях задаёт диаметр плеча 20 мм, длину 60 мм и участки Ø12 × 15, Ø8 × 15. Требования не переписываются автоматически из плана игрока.
4. Проверяет каталог: подходящая стальная заготовка Ø20 × 60, токарный станок, проходной резец, разрешённое точение с положительной авторской длительностью.
5. Проверяет карту: стол и склад на разрешённых точках, минимум одна свободная точка для выбранного станка.
6. Выполняет «Проверить». Ошибки выбирают соответствующую ноду либо указывают конкретную настройку; некорректный уровень не запускается.
7. В тестовом запуске проходит своё задание с операциями Ø12 × 15, затем Ø8 × 15. Проверяет одну неверную попытку, например алюминиевую заготовку.
8. Экспортирует JSON. Импортирует в отдельном чистом профиле браузера; повторно проходит задание и получает тот же результат.

**Результат:** уровень воспроизводится без вмешательства разработчика. В инструкции отдельно пояснены каталог, независимые требования, порядок участков и разница режимов «Готовый план» / «План игрока».

Редактор должен сохранять незавершённый черновик; сохранение не равняется разрешению запуска. Ошибочный импорт не заменяет текущий уровень. Перемещение, размер и группы влияют на оформление, но не меняют производственный результат. Добавление сложного мастера создания уровней не обязательно, если этот сценарий выполняется существующими формами.

## 6. Данные, модель и надёжность

- Авторское описание v4 и план попытки разделены. Экспорт не включает текущее изготовление, склад и таймер попытки. После перезагрузки восстанавливается авторский уровень, а не незавершённая обработка.
- Предпросмотр и изготовление используют общие чистые функции совместимости и изменения геометрии. Побочные эффекты предпросмотра запрещены.
- У каждой операции собственный инструмент; длительность задаёт автор. Ученик не меняет длительность ради успеха.
- Успех зависит от материала, формы, размеров и нормализованной геометрии участков. Он не требует совпадения ID или количества операций с авторским решением.
- Доступность действий и повторная проверка команд остаются в ядре. Заблокированная кнопка не является единственной защитой.
- Повторные клики, выход во время обработки, сброс и возврат в игру не оставляют дубли предметов, обработок или подписок.
- Ошибки формата, изображения и localStorage объясняются; исходное сохранение не теряется. При невозможности сохранить в браузере остаётся возможность экспорта.
- Формат и миграции v1/v2/v3 → v4, стабильные ID нод/портов и границы модели/представления сохраняются. Для действительно необходимой смены контракта нужна отдельная согласованная задача.

## 7. Что даёт ИИ при разработке

ИИ позволяет прорабатывать сложную архитектуру, алгоритмы нормализации геометрии, проверки графов, диагностику несоответствий, взаимодействия редактора и сценарии регрессии. Не вводим искусственное правило «только простые изменения». Большую задачу разбиваем на проверяемые части ради контроля результата.

Для каждой части ИИ должен подготовить конкретное изменение, необходимые проверки и объяснение результата. Проверка включает diff, архитектурные инварианты, тесты, сборку и браузер там, где меняется видимое поведение. Материалы для ученика утверждает человек, понимающий учебную задачу. Сложность учитываем как риск качества и сопровождения, но не как автоматический запрет.

В продукте ИИ не оценивает попытки и не ведёт ученика. Успех вычисляет детерминированная модель. На этапе после MVP возможны только отдельно согласованные варианты поддержки: правила и готовые ответы, простой классификатор вопроса, направление к подходящей инструкции или оператору. Разработку такой поддержки сейчас не начинаем.

## 8. Пакеты работ и связь с текущим кодом

## 9. Матрица приёмки и определение готовности

| Проверка | Свидетельство прохождения |
| --- | --- |
| Автотесты и сборка | `npm test` и `npm run build` успешно завершены на версии для выпуска; результат и версия записаны |
| Задания A/B/C | Все контрольные маршруты из раздела 3 пройдены в настоящем браузере; отмечены браузер и версия сборки |
| Планирование | Пустые поля, несовместимость, порядок операций, равнозначные планы, чистый предпросмотр и исправление проверены |
| Действия ядра | Повторный запуск, перенос во время обработки, отмена цели, сброс на каждом шаге и повторное прохождение не нарушают состояние |
| Отображение | Обе заявленные браузерные среды, размеры/профиль деталей, кнопки и подсказки проверены визуально; jsdom не считается визуальной проверкой |
| Редактор | Создан вариант раздела 5; проверены ошибки графа, связи, перетаскивание/размеры/группы при затрагивании геометрии |
| Перенос и сохранения | Сохранение/перезагрузка, экспорт/чистый импорт, ошибочный импорт и поддерживаемые миграции проверены без потери данных |
| Учебный пилот | Наблюдения минимум по пяти ученикам и одному учителю; достигнуты критерии ниже |

Пилот проводит владелец/учитель с реальными участниками. Учеников обозначаем У1–У5. Дедлайнов и лимитов времени нет. Всем дают одинаковую начальную инструкцию; подсказки приложения разрешены, выдачу готового плана взрослым фиксируют как помощь.

Условия учебной приёмки:

- Не менее 4 из 5 учеников завершают ось без выдачи готового решения взрослым и самостоятельно исправляют хотя бы одну намеренно допущенную ошибку.
- Те же ученики правильно объясняют минимум 2 из 3 вопросов: почему тонкая заготовка не подходит; почему неверный материал не засчитывается при правильных размерах; как порядок и размеры участков влияют на профиль.
- Не менее 4 из 5 учеников завершают брусок без готового плана и объясняют связь суммарного снятия с конечной высотой.
- Учитель выполняет сценарий своего варианта и переноса без правки кода или помощи разработчика.

При провале фиксируем конкретное препятствие, исправляем и проверяем повторно. Маленький пилот даёт первую обратную связь; не объявляем его доказательством эффективности для всех школьников.

Выпуск MVP готов, когда приняты A/B/C, выполнен авторский сценарий, прошла техническая матрица и достигнуты условия пилота. Блокирующие проблемы — невозможность пройти правильный маршрут, ложный успех, потеря данных, несовпадение предпросмотра/изготовления, отсутствие пути исправить ошибку или непонятные необходимые действия. Косметические недочёты допустимы только если не мешают чтению и прохождению, и перечислены явно.

Комплект выпуска: приложение/сборка, три задания, инструкция запуска, инструкция ученика, инструкция учителя, перечень проверок и известных ограничений. Метки «готово» ставим только со свидетельством.

## 10. Как следуем документу

Каждая задача указывает ID пакета, пользовательский результат и критерии проверки. Если она не закрывает требование MVP и не исправляет регрессию, предлагаем её отдельно после MVP. Новые возможности оцениваем по пользе, а не отвергаем только из-за сложности или использования ИИ.

Шаблон задачи: «M4: после сдачи детали с неверным материалом показать ожидаемый и фактический материал; правильный результат по-прежнему завершает уровень; проверить оба случая в модели и браузере».

Документ закреплён ссылками из README и AGENTS.md. Общая концепция согласована с уточнениями пользователя; расширенная детализация ожидает просмотра. Реализация новых продуктовых изменений — следующая отдельная работа. Даты и сроки не являются частью плана.

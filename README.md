# Учебный завод

Образовательная и олимпиадная платформа для 5–11 классов в стиле инженерной игры: изометрический цех, миссии, карта направлений, результаты, олимпиады и редактор заданий для организаторов. TypeScript (strict), React 19, Phaser 3, React Flow (`@xyflow/react`) и Vite 7. Вся графика процедурная (геометрия Phaser и SVG), шрифты Onest и Unbounded подключены локально. Без внешних изображений, CDN, сервера и регистрации: прогресс хранится в `localStorage`.

## Экраны

Навигация по хэшу (`#/…`), боковая панель скрывается на полноэкранных экранах.

| Адрес | Экран |
| --- | --- |
| `#/hub` | Хаб: продолжить, рекомендуемая миссия, уровень и звание, ближайшая цель |
| `#/map` | Карта миссий: 6 направлений, статусы «заблокировано / доступно / в процессе / пройдено / пройдено на максимальную оценку», чертёж и условия открытия |
| `#/mission/<id>` | Игровой экран: вводный бриф, большая изометрическая сцена, панель задания, контекстная панель объекта, камера (перетаскивание, колесо, `+`/`−`/`0`), пауза, настройки, горячие клавиши `1/2/3`, `Esc` |
| `#/result/<id>` | Результат: оценка, точность, время, критерии, разбор ошибок, XP, достижения, следующая миссия |
| `#/olympiads` | Олимпиады: режим тренировки и строгий режим, этапы |
| `#/olympiad/<id>/<этап>` | Этап олимпиады |
| `#/profile` | Профиль: уровень, звание, достижения, история |
| `#/editor` | Редактор заданий организатора (прежний редактор на React Flow) |

Исходная простая демка по-прежнему доступна по `/?demo=classic`.

## Что реально работает, а что запланировано

Работает: обработка заготовки на токарном станке (одна и несколько операций), проверка допустимых команд ядром, ошибки и подсказки, оценка, прогресс, олимпиадный режим с таймером и одной попыткой на этап, редактор с импортом, экспортом, проверкой и тестовым запуском.

Каталог инструментов, план игрока, фрезерование, промежуточные склады, группы и отмена правок доступны в редакторе.

Отдельные миссии только запланированы и помечены в интерфейсе как «Запланировано», запуску не подлежит: выбор инструмента, измерение штангенциркулем, сборка механизма, поиск неисправности, настройка маршрута, оптимизация, программирование автоматики. Олимпиады, кроме «Юного технолога», и их данные демонстрационные; это указано в интерфейсе.

## Оценка и прогресс

Оценка детерминирована и считается только по ходу попытки (максимум 1000):

- выполнение 500: заготовка закреплена, операции выполнены, деталь сдана;
- точность 300: −60 баллов за каждую ошибку;
- самостоятельность 100: −30 за каждую подсказку; в тренировке с наставником фиксированно 40; в олимпиаде всегда 100;
- время 100: `100 × норма / время`, не больше 100 (норма = сумма времени операций + 30 с); засчитывается только за завершённую работу.

Звёзды: 3 при ≥950, 2 при ≥700, 1 за выполненную миссию. Уровень, XP, звание, зоны и достижения **не влияют на оценку**: они только открывают доступ и показывают прогресс. XP: за первое прохождение `балл / 8`, за улучшение `разница / 16`, за этап олимпиады `балл / 16`; уровень `1 + ⌊√(XP / 60)⌋`. Звания: Стажёр, Оператор станка, Наладчик, Технолог, Инженер. Токарный участок открывается после миссии «Два участка» и достижения 3 уровня.

Олимпиада: подсказок, паузы и перезапуска нет, недоступная команда считается ошибкой, попытка тратится в момент старта (закрытие страницы её не возвращает), по истечении времени работа сдаётся с частичным результатом.

Совместная работа: [инструкция для двух разработчиков](docs/COLLABORATION.md), [правила Codex](AGENTS.md).

Перед объединением изменений логики и оформления выполните затронутые сценарии [браузерной приёмки](docs/BROWSER_ACCEPTANCE.md). Для параллельной работы используйте отдельные рабочие папки и порты по инструкции совместной разработки.

## Запуск через Docker

Запустите Docker Desktop и выполните в папке проекта:

```sh
docker compose up --build -d
```

Откройте **http://localhost:8081**. Docker устанавливает зависимости, выполняет тесты и сборку, затем nginx раздаёт готовый сайт. Node.js на компьютере не нужен.

```sh
docker compose logs
# Остановить контейнер:
docker compose down
# Если порт 8081 занят:
DEMO_PORT=8090 docker compose up --build -d
```

После изменения кода повторите `docker compose up --build -d`. При разработке через Docker изменения исходников требуют пересборки; горячая перезагрузка доступна при локальном запуске Vite.

## Локальная разработка

Для разработки и тестов нужен Node.js 22.22.2+ в ветке 22, 24.15+ в ветке 24 или 26+. Docker уже использует подходящую версию.

```sh
npm ci
npm run dev
```

Откройте адрес Vite (обычно http://127.0.0.1:5173).

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

Тесты (`tests/*.test.ts`) запускаются через `node --import tsx --test`; экранные тесты используют `react-dom/server` и jsdom, поэтому Phaser и CSS в них не подгружаются (Phaser грузится лениво только на игровом экране, CSS подключается в `bootstrap.tsx`). Сборка находится в `dist/`. Phaser выделяется Vite в общий модуль; его размер вызывает информационное предупреждение о большом чанке.

## Готовый пример и прохождение в редакторе

При первом открытии редактора загружается полностью подключённый и размещённый пример. Если в браузере сохранён корректный уровень, загружается он.

1. Откройте `#/editor` и нажмите «Протестировать» (запуск сцены с журналом администратора) либо выберите миссию на `#/map`.
2. Прочитайте вступление и нажмите «Начать».
3. Выберите заготовку на столе → «Установить в станок» → выберите станок.
4. На выбранном загруженном станке нажмите «Обработать» и дождитесь окончания.
5. Выберите готовый валик в станке → «Отправить на склад» → выберите склад.

«Отменить выбор цели» отменяет ожидаемый выбор станка/склада. «Начать заново» сбрасывает весь сценарий и обработку. Выход в редактор освобождает сцену и подписки. Игра приостанавливается в неактивной вкладке.

Кнопка «Пример»: сталь Ø20 × 60 мм, проходной резец, обработка до Ø12 мм на участке 30 мм за 3 секунды, склад на одну деталь. «Приветствие» загружает текстовый уровень без оборудования. «2 операции» загружает обработку двух участков: Ø12 × 30 мм за 3 секунды, затем Ø8 × 15 мм за 2 секунды.

## Быстрое создание нод

В графе дважды щёлкните ЛКМ по свободному фону или нажмите «Найти ноду». Введите название, назначение, синоним («резец», «фрезерный», «маршрут», «сетка») либо внутренний тип (`tool`, `lathe`). Регистр, «е/ё» и лишние пробелы не важны; несколько слов уточняют поиск. Стрелки ↑/↓ выбирают результат, Enter или клик создают ноду, Escape и клик снаружи закрывают окно. Пустой запрос показывает недавние типы и категории.

Нода появляется у точки вызова с учётом масштаба и смещения; кнопка использует центр видимой области. При занятом месте выбирается ближайшее свободное. На пустом фоне группы новая нода входит в эту группу. Повторную «Карту» поиск не создаёт и предлагает перейти к существующей. Библиотека и перетаскивание сохранены; ЛКМ перемещает поле, ПКМ выделяет рамкой, колесо меняет масштаб.

«Отменить» / Cmd+Z (Ctrl+Z) отменяет создание вместе с принадлежностью к группе; «Повторить» / Cmd+Shift+Z (Ctrl+Shift+Z) восстанавливает тот же ID и положение. Недавние типы сохраняются отдельно как предпочтения редактора; запрос, окно и история не входят в JSON уровня. Недоступность хранилища не мешает поиску.

## Создание уровня

- «Новый уровень» создаёт пустое описание; «Пример» восстанавливает готовый пример. Эти действия заменяют текущую несохранённую работу; сохраните/экспортируйте её заранее.
- Добавляйте ноды кнопками «+» в библиотеке, перетаскивайте их в граф или выберите тип в верхней панели и нажмите «+ Добавить ноду». Библиотека доступна и на вкладке карты; добавление переводит в граф. Новая нода получает свободное место и автоматически попадает в видимую область. Для уровня-приветствия нужны только начало, вступление и завершение. Оборудование требуется только при наличии производственного задания. Для производственного цикла нужны начало, задание, ожидание, завершение и по одной ноде заготовки, инструмента, станка и склада; операций может быть несколько. Вступления необязательны; их может быть несколько.
- Выберите ноду: размер меняется перетаскиванием маркеров по углам/краям или полями «Ширина ноды» и «Высота ноды» справа. Размер сохраняется в JSON отдельно от позиции и параметров. Измените её параметры справа. Тексты, размеры и время сразу обновляются в описании уровня.
- Перетаскивайте ноды за заголовки с маркером ⠿; связанные линии следуют за портами. Связь можно создать двумя кликами по подписям: сначала выход справа, затем совместимый вход слева. Свободные совместимые входы подсвечиваются. Также доступна кнопка «+ Добавить связь» в поле графа: выберите выход и вход в списках. Перетаскивание между увеличенными портами тоже работает. Если вход занят или типы несовместимы, показывается причина; для переподключения выберите старую линию и нажмите Delete/Backspace. Выберите ноду или связь и нажмите Delete/Backspace для удаления. Масштабируйте колесом или кнопками; перемещайте рабочее поле перетаскиванием пустого места. «Показать все ноды» возвращает весь граф в видимую область. Ноды и связи видны на вкладке «Граф сценария»; вкладка «Карта» показывает объекты цеха.
- На вкладке «Карта» выберите объект слева и нажмите свободную клетку. Размер сетки можно менять справа (до 8 × 8). Координаты ноды и координаты объекта независимы. При уменьшении сетки объекты за её границами нужно разместить заново.
- «Проверить» показывает ошибки и конкретные ноды; нажатие на ошибку выбирает её ноду. Некорректный уровень не запускается.
- «Сохранить» записывает уровень или незаконченный черновик в localStorage этого браузера. После перезагрузки можно продолжить работу. Некорректный черновик нельзя запустить. «Экспорт JSON» также позволяет сохранить незаконченный черновик. «Импорт JSON» принимает только полностью корректный уровень версии 1; при ошибке текущее описание остаётся без изменений.

Для проверки основного критерия измените текст ноды «Вступление», диаметр/длину участка и время в ноде «Операция точения». Запустите тест: вступление, прогресс, подпись размеров и форма готового валика будут соответствовать новым параметрам. Возврат из теста сохраняет описание редактора.

## Типы связей и нод

Золотые пунктирные связи — **выполнение**, голубые сплошные — **данные**. Оборудование не требуется для цепочки **начало → вступления → завершение**. Порты данных типизированы: заготовка, инструмент, операция, станок, склад. Несовместимые соединения и несколько связей в один вход запрещены при подключении и проверяются валидатором. Связи данных описывают ссылки; они не переносят предмет и не запускают станок.

| Нода | Назначение |
| --- | --- |
| Начало уровня | Единственная точка входа |
| Вступление | Заголовок/текст; ждёт кнопки «Начать» |
| Заготовка | Название, материал, диаметр и длина |
| Инструмент | Предустановленный проходной токарный резец |
| Операция точения | Заготовка, необязательная предыдущая операция, диаметр/длина участка и длительность |
| Токарный станок | Название, ссылки на инструмент и операцию |
| Склад | Название и целочисленная положительная вместимость |
| Задание | Цель/инструкция, ссылки на нужный станок и склад |
| Ожидать деталь на складе | Склад и операция с ожидаемыми характеристиками |
| Завершить уровень | Текст успеха и повторное прохождение |

Последовательность производственного уровня: **начало → задание → ожидание → завершение**. Между шагами можно добавлять вступления; каждое ждёт подтверждения игрока. Пример содержит одно вступление перед заданием. Задание активирует производство и передаёт выполнение ожиданию. Ожидание проверяет текущее состояние сразу при активации и затем слушает событие поступления детали. Завершение запускается ровно один раз.

| Файл | Ответственность |
| --- | --- |

| `src/platform/` | Миссии и направления, оценка (`scoring`), сессия (`session`), прогресс и достижения (`progress`), олимпиады (`olympiads`), итоги (`result`) |
| `src/screens/` | Экраны: хаб, карта, игровой экран, результат, олимпиады, профиль, чертёж |
| `src/GraphEditor.tsx` | Редактор React Flow, ноды/порты, перетаскивание, связи и фокус добавленной ноды |
| `src/editorFlow.ts` | Согласование графа с моделью; сохранение полного состояния React Flow отдельно от уровня |
| `src/connections.ts`, `src/ConnectionBuilder.tsx` | Общие правила соединения и форма выбора выходов/входов |
| `src/Workshop.tsx`, `src/scene/` | Адаптер сессии, камера и геометрическая изометрическая сцена Phaser (грузится лениво) |
| `src/presentation/workshopDrawing.ts` | Сохранённый модуль прежней отрисовки: геометрия цеха, детали и общая проекция клеток; новая сцена использует `src/scene/` |
| `src/classic.ts`, `src/production.ts` | Сохранённая исходная демка |

Ядро и компилятор не импортируют React, Phaser, DOM или React Flow. Игровые кнопки используют `core.can`, а непосредственные вызовы команд повторно проверяют те же правила. На старте теста компилируется отдельная копия определения. Формат JSON содержит версию, ID/название, ноды/параметры, связи/порты, позиции, сетку и размещение; состояние прохождения в него не записывается.

Обработка считает время через `tick`, без отложенных таймеров. Сброс/выход отменяет обработку и очищает подписки, поэтому старый экземпляр не влияет на новый.

## Ограничения первой версии

В производственном уровне одна физическая заготовка, один станок, один предустановленный резец и один склад; последовательных операций может быть несколько. Текстовые уровни не требуют производственных объектов. Последовательный производственный цикл с произвольными ID и текстами, необязательными вступлениями и собственным размещением. Циклы, параллельные ветви, дубли физических объектов/обязательных шагов и неверный порядок производства показывают понятные ошибки при проверке. В редактор можно добавлять любые ноды и сохранять незаконченные черновики. Вместимость можно увеличить, но в уровне всё равно существует только одна деталь. Модель точения условная, без физики и расчёта сил; уменьшение диаметра и длина участка проверяются. Режимы администратора и игрока локальные, без разграничения доступа. Для комфортного редактирования графа рекомендуется настольный браузер.

## Добавление нового типа ноды

1. Добавьте тип в `NODE_TYPES` и определение в `registry`: название, параметры с начальными значениями, входные/выходные типизированные порты и правила параметров. Библиотека/панель свойств используют этот реестр автоматически.
2. Обновите правила количества и допустимой цепочки в `validation.ts` для выбранного расширения. Межобъектные проверки добавляйте там же.
3. Добавьте компиляцию ссылок/параметров в `compiler.ts`. Если это исполняемая нода, реализуйте её запуск/завершение в `FactoryCore.activate` и при необходимости событие.
4. Для размещаемого объекта добавьте разрешённый тип в операции карты/валидатор и отрисовку в `presentation/workshopDrawing.ts` и выбор в `Workshop.tsx`.
5. Добавьте тесты нового поведения и несовместимых соединений. При изменении структуры JSON измените версию формата и реализуйте явную миграцию.

## Проверки

Тесты покрывают полный цикл, запрет хранения необработанной заготовки, неверные цели и прямые запрещённые команды, повторные действия, нужные характеристики/склад, ожидание уже поступившей детали, параметры нод без изменения кода, сброс/выход во время обработки, очистку подписок, связи/циклы/порты, размеры, размещение/удаление и JSON/localStorage. Исходные три теста простой демки сохранены.

Тесты редактора проверяют сохранение размеров и данных перетаскивания, движение обоих концов связей для всех типов нод (включая начало уровня), создание полностью собственного уровня с новыми ID и прохождение. Тесты React-интерфейса в jsdom выполняют настоящие клики и события мыши: добавление в пустой проект, повторные добавления, движение SVG-линий при перетаскивании всех десяти типов и сохранение/восстановление черновика. Размеры и состояние редактора не попадают в JSON уровня. Эти проверки используют моделируемую геометрию DOM и не заменяют визуальную проверку в браузере.

## Несколько токарных операций

Быстрее всего нажать «2 операции» и изменить параметры готовой цепочки. Чтобы собрать её самостоятельно:

1. Добавьте несколько нод «Операция точения». Выход заготовки подключите ко входу «Заготовка» **каждой** операции.
2. Выход «Операция» первой ноды подключите ко входу «Предыдущая операция» второй. Аналогично соедините третью и следующие. У первой операции вход «Предыдущая операция» оставьте свободным.
3. Выход **последней** операции подключите к станку и к входу «Требования» ожидания детали на складе. Все остальные подключения задания, склада и инструмента остаются как в одном цикле.
4. В игре установите заготовку один раз. Нажимайте «Обработать 1 / N», затем «Обработать 2 / N» и далее. На склад можно отправить только результат всех операций.

Каждая операция обрабатывает следующий отдельный участок вдоль валика. Их суммарная длина не должна превышать длину заготовки; диаметры участков должны быть меньше исходного. Это несколько участков одной детали, а не повторные проходы резцом по одному участку. Форма готового валика показывает все участки. Сброс отменяет текущую операцию и очищает уже обработанные участки.

## Уровень-приветствие

Нажмите «Приветствие» или создайте начало, одно/несколько вступлений и завершение. Соедините их связями выполнения в нужном порядке. Измените тексты и запустите тест. Каждое вступление ждёт кнопки «Начать», затем переход к следующему тексту или итоговому сообщению. Стол, станок, инструмент, операция и склад для такого уровня не нужны.

## Примеры и прохождение

При первом запуске открывается токарный пример. Корректное сохранение браузера загружается автоматически; v1/v2/v3 мигрируют в v4. Ошибка не удаляет исходное сохранение.

- «Ось: план игрока»: самостоятельный выбор каталога, размещение станка, два-три участка стальной оси. Пошаговое прохождение ниже.
- «Пример»: цилиндр из стали Ø20 × 60 мм, проходной резец, участок Ø12 × 30 мм за 3 секунды.
- «2 операции»: отдельные участки Ø12 × 30 мм и Ø8 × 15 мм за 3 и 2 секунды.
- «Два станка»: Ø20 × 60 мм → участок Ø12 × 30 мм → промежуточный склад → тот же предмет на втором станке → новый участок Ø8 × 15 мм → конечный склад.
- «Фрезерный пример»: брусок 60 × 40 × 20 мм, торцевая фреза, снятие 5 мм за 3 секунды, результат 60 × 40 × 15 мм.
- «Приветствие»: текстовый уровень без оборудования.
- «Проверка выбора»: две ветви оператора. Правильная конфигурация ведёт к производству, неверная — к пояснению и отдельному завершению. Для второй ветви поменяйте **ожидаемый материал** в операторе на «Алюминий», оставив стальную заготовку. Физически невозможную конфигурацию валидатор не запустит.

Производственные примеры: **начало → вступление → задание → ожидание → завершение**.

1. Нажмите «Протестировать» (с журналом) или «Игрок».
2. Прочитайте вступление и нажмите «Продолжить». Каждое вступление ждёт отдельного подтверждения.
3. Выберите заготовку на столе → «Установить в станок» → выберите станок.
4. На выбранном станке нажмите «Обработать 1 / N». После завершения продолжайте следующие операции по порядку.
5. Выберите готовую деталь в станке → «Отправить на склад» → выберите склад.

В цехе можно перетаскивать саму заготовку со стола на совместимый станок, готовую деталь со станка на склад, а из промежуточного склада — на следующий станок. Подходящие цели подсвечиваются голубым. Отпускание вне цели, Escape или потеря фокуса отменяют перенос и оставляют предмет на месте. Во время обработки перенос запрещён; конечный склад предмет не выдаёт.

Действия открываются рядом с объектом по нажатию: на заготовке — «Установить в станок», на загруженном станке — «Обработать», на завершившем обработку станке/готовой детали — «Отправить на склад», на промежуточном складе — «Взять заготовку». Кнопки перемещения позволяют выбрать цель следующим кликом, без перетаскивания. Правая панель показывает задание, размеры и результат.

«Отменить выбор цели» отменяет ожидание клика по станку/складу. Во время обработки повторный запуск и перемещения запрещены. Команды ядра повторно проверяют доступность. «Начать заново» сбрасывает всю попытку и промежуточную геометрию. Выход освобождает сцену и подписки. Завершение рассчитывает tick, отложенных таймеров нет. Неактивная вкладка приостанавливает сцену.

Счётчик становится 1 после хранения фактической детали. Успех появляется только при соответствии материала, формы, размеров и участков **независимым требованиям**. В режиме «Готовый план» при несовпадении вернитесь в редактор и проверьте техпроцесс/требования. В «Плане игрока» исправляйте план прямо в игре.

Исходная демка сохранена по **http://localhost:8081/?demo=classic**; её модель и тесты не изменены.

## Создание уровня

«Новый уровень» создаёт пустое описание. Примеры заменяют текущую работу; сохраните или экспортируйте её заранее.

Добавляйте ноды кнопками «+» слева, перетаскиванием типа в граф или выбором типа в верхней панели. Добавление с карты переводит в граф; нода появляется на свободном месте в видимой области. Выберите ноду и настройте параметры справа.

**Cmd+Z (macOS) / Ctrl+Z (Windows)** отменяет последнее редактирование уровня; также доступна кнопка «Отменить». Поддерживаются ноды, связи, параметры, группы и размещения. Одно перетаскивание или изменение размера — один шаг отмены; ввод в одном поле объединяется до потери фокуса или отдельной команды. В текстовых полях сочетание сохраняет обычную отмену ввода браузера. Выделение, масштаб и перемещение поля не записываются в историю. История хранит до 50 правок в текущем сеансе, не входит в JSON и очищается при открытии другого примера, нового уровня или импорте. В режиме игрока редакторская отмена отключена. Чтобы сохранить отменённые изменения, нажмите «Сохранить».

Размер меняется **только перетаскиванием границ и углов** выбранной ноды. Поля ширины/высоты из панели свойств удалены. Размер и положение сохраняются в JSON как оформление редактора; производственная логика и проверка результата их не используют. Перемещение за заголовок ⠿ и изменение размера обновляют порты и линии.

Связи создаются двумя кликами по подписям (выход справа → совместимый вход слева), перетаскиванием между портами или через «+ Добавить связь». Совместимые входы подсвечиваются. Выберите линию и Delete/Backspace для переподключения; те же клавиши удаляют выбранные ноды. Колесо меняет масштаб; левая кнопка на пустом поле перемещает поле, правая выделяет ноды рамкой. Средняя кнопка также перемещает поле; Shift + правая рамка добавляет к выделению. «Показать все ноды» возвращает граф в видимую область.

На вкладке «Карта» выберите заготовку, станок, стол или склад слева, затем свободную клетку. Сетка до 8 × 8, один объект на разрешённой точке. Нода «Карта» задаёт размеры и число точек; во вкладке карты доступны отметка/снятие и перенос свободных точек. Позиции объектов независимы от позиций нод. Уменьшение карты и числа точек блокируется, если затрагивает занятые точки; сначала снимите или переместите объекты. Инструмент/техпроцесс/требования детали — данные графа, отдельных предметов на карте не создают.

«Проверить» показывает конкретные ошибки; клик выбирает соответствующую ноду. Некорректный уровень не запускается. «Сохранить» и «Экспорт JSON» поддерживают незаконченные черновики. «Импорт JSON» принимает полностью корректный v4 или поддерживаемые v1/v2/v3 после миграции; ошибка не заменяет текущее описание. Состояние попытки в сохранение не входит.

## Типы нод

| Нода | Назначение |
| --- | --- |
| Начало уровня | Единственная точка входа выполнения |
| Вступление | Необязательные заголовок/подпись и PNG/JPEG/WebP; «Продолжить» |
| Задание | Только заголовок и текст; активирует производство; вход/выход выполнения |
| Ожидать деталь на складе | Входы склада/требований; количество 1; выход фактической «Детали» после успешного ожидания |
| Проверить выбор | Проверки конфигурации и фактической детали; независимые требования; две ветви |
| Завершить уровень | Текст результата; завершение один раз |
| Заготовка | Материал, название, цилиндр (диаметр/длина) или брусок (длина/ширина/высота), мм |
| Инструмент | Категория, затем инструмент: проходной/подрезной/отрезной резец, концевая/торцевая фреза |
| Техпроцесс | Упорядоченный список операций: добавление, удаление, ↑/↓; стабильные ID |
| Станок | Токарный/фрезерный; в готовом плане входы заготовки, инструмента, техпроцесса; в каталоге — определение альтернативы без этих входов |
| Полученная деталь | Независимые материал/форма/размеры/участки; вход станка в готовом плане, вход каталога в плане игрока |
| Каталог | Ссылки на 1–5 определений каждой категории; разрешённые операции с авторской длительностью |
| Стол | Фиксированная точка выбранной заготовки в плане игрока |
| Склад | Конечный/промежуточный, вместимость; промежуточный выдаёт источник заготовки |
| Подсказка | Текст, панель/модальное окно, подтверждение и частота; выполнение либо событие |
| После действия | Успешное действие любого или выбранного объекта → событие подсказки |
| Карта | Размеры и число точек; без портов; один источник конфигурации в grid |

Станок развивает прежний внутренний тип `lathe`. Ноды `turning` в v2 заменены списком `process`; дубликатов старых типов в библиотеке нет.

## Подключение графа

Золотой пунктир — **выполнение**, голубые линии — **данные**. Выходы заготовки, инструмента и техпроцесса подключите к одноимённым входам станка. Выход станка → вход «Полученной детали». Выход полученной детали и выход склада → входы ожидания. Задание не имеет ссылок на оборудование.

У данных одиночные входы. Выход данных может использоваться и станком, и оператором проверки. Каждый выход выполнения имеет одну следующую ноду. Оператор выбирает «Правильно» **или** «Неправильно»; обе ветви подключены и достигают завершения. Альтернативные ветви могут сходиться в один вход выполнения; это не параллельный запуск. На каждом производственном пути задание предшествует ожиданию, а ожидание — завершению. Несколько последовательных этапов используют один физический предмет; каждому этапу соответствует свой станок и ожидание. Циклы, параллельные выходы, отсутствующие ссылки и недостижимые ноды сценария запрещены.

Ожидание проверяет уже хранимую деталь при активации и затем при событии поступления. Числа сравниваются с абсолютным допуском 0.000001 мм плюс относительным 1e-9 для погрешности арифметики. Это не допуск реальной технологии.

## Реализованные операции и требования

**Продольное точение:** цилиндр, токарный станок и проходной резец. Каждая операция создаёт следующий отдельный участок длины L и диаметра D; суммарная длина не превышает длину заготовки, каждый D меньше исходного диаметра. На рисунке сначала остаётся необработанная часть, затем участки в порядке техпроцесса. Это отдельные участки, а не повторные проходы по одному месту. Несколько операций находятся в одной ноде «Техпроцесс». На склад отправляется результат всех операций.

**Фрезерование верхней плоскости:** брусок, фрезерный станок и концевая либо торцевая фреза. Каждая операция уменьшает текущую высоту на глубину снятия; длина/ширина сохраняются, конечная высота положительна. Геометрия и анимация условные, без физики.

Подрезные и отрезные резцы перечислены с пометкой, что соответствующие операции пока не реализованы. Подрезки, отрезания и пазов среди команд/операций нет; несовместимую производственную конфигурацию валидатор запрещает.

«Полученная деталь» хранит независимые требования. Для валика задайте диаметр оставшегося плеча (при обработке всей длины — максимальный диаметр участков), общую длину и участки по порядку. Для равномерно обработанного цилиндра можно оставить список участков пустым и задать конечный диаметр. Для бруска — конечные длину, ширину, высоту. **«Заполнить из техпроцесса»** копирует результат один раз; дальнейшее изменение техпроцесса не переписывает требования.

«Проверить выбор» сравнивает конфигурацию с независимо заданными ожидаемыми значениями. Включите нужные флаги и подключите типизированные входы. Проверяются типы станка/инструмента, материал/форма/размеры заготовки, порядок/типы/параметры/время операций (их ID не сравниваются). Оператор срабатывает один раз, записывает сообщение и продолжает выбранную ветвь. В режиме «План игрока» строгие проверки выбранного маршрута запрещены: допустима проверка фактического результата.

Текстовый уровень: **начало → одно/несколько вступлений → завершение**, без оборудования. Оператор проверки также допустим; обязательность входов определяется флагами.

## Изображения и сохранение

Во вступлении загрузите/замените PNG, JPEG или WebP и посмотрите предпросмотр; «Удалить изображение» оставляет текст. SVG, HTML и временные blob/object URL запрещены. Тип проверяется по содержимому, затем браузер действительно декодирует картинку через Image.decode при загрузке, импорте и восстановлении.

Ограничения: **512 КиБ на файл**, **2048 × 2048 пикселей**, **1 МиБ изображений суммарно**, **2 МиБ UTF-8 JSON**. Картинки хранятся как data URL в определении уровня. При ошибке декодирования или переполнении localStorage показывается причина; проект можно экспортировать. Квота браузера может быть меньше предела JSON.

## Совместимость и миграция

Формат **v4**, ключ localStorage `factory-level-v4`. Если его нет, читается v3, затем v2, затем v1. Миграция происходит в памяти; старые ключи **не удаляются и не перезаписываются**. v4 появляется после явного сохранения. Миграция v3 добавляет `productionMode: "ready"` и пустые `groups`, сохраняя ID, геометрию, карту, изображения, подсказки и промежуточные склады.

v1 сначала проходит прежнюю миграцию: операции объединяются в техпроцесс на месте последней ноды; их ID/параметры/порядок сохраняются, оборудование отсоединяется от текста задания, создаются независимые требования детали. Положение и размер сохраняемых нод остаются прежними.

Из v2 размеры grid переносятся в единственную конфигурацию v3, создаётся нода «Карта». На занятых клетках создаются разрешённые точки со стабильными ID; размещения теперь ссылаются на точку (`pointId`), а не дублируют координаты. Старые склады становятся конечными. Тексты, изображения, ID объектов и размеры нод сохраняются. Текстовому уровню без объектов карта не добавляется.

Незавершённый v1-черновик с отсутствующими ссылками или циклом может не мигрировать: показывается причина, исходные данные остаются нетронутыми. Поддерживаются незаконченные v4-черновики и миграция v3-черновиков. Ошибка импорта не заменяет проект редактора.

## Проверки и ограничения этапа

Тесты покрывают оба цикла, несколько участков, обе ветви проверки, соответствие/несоответствие требований, текстовые уровни, граф/совместимость, миграцию реальных v1-примеров, изображения и ошибки сохранения, повторные действия и сброс во время обработки, промежуточный склад, подсказки и карту. UI-тесты jsdom проверяют формы, инструменты, списки операций, копирование требований, загрузку/удаление изображений, перетаскивание нод, изменение размера границами и обновление линий. Декодер изображений в тестах моделируется; они не заменяют браузерную проверку PNG/JPEG/WebP. Тесты рисования проверяют участки и уменьшение высоты бруска.

Одна физическая заготовка; несколько последовательных станков и складов, со своими инструментами/техпроцессами/требованиями; операций до 20, требуемое количество 1. До 100 нод и 200 связей. Ациклический сценарий с альтернативами. Без расчётов резания, сервера и разграничения ролей. Для графа рекомендуется настольный браузер.

В плане игрока — один выбранный станок, один стол, один конечный склад и одна деталь. Станки каталога — альтернативы. До 5 вариантов в каждой категории, до 20 операций и до 50 групп. Группы не вложены, не сворачиваются и не являются подграфами. Кампания, экономика, ходы, массовое производство и новые виды обработки не добавлены. Готовые многоэтапные маршруты с промежуточными складами сохранены.

Для нового типа ноды обновите реестр, проверку и компиляцию, при необходимости ядро и readonly-данные представления. Добавьте проверки совместимости/поведения. При изменении структуры сохранений вводите версию и явную миграцию.

## Подсказки и события

«Подсказка» в сценарии подключается входом/выходом выполнения. При подтверждении ждёт «Продолжить», без него сразу продолжает сценарий и оставляет сообщение в панели. Способ показа независим: неподтверждаемое модальное окно можно закрыть, но основная цепочка уже продолжена. Очередь показывает только одно окно одновременно; события не накладывают подсказку поверх вступления.

Для подсказки после действия добавьте «После действия», выберите событие и конкретный объект (или любое действие). Соедините выход «Событие» со входом подсказки «После действия». Поддерживаются установка, завершение операции, поступление на склад, успешное получение со склада и успешная проверка выбора. «Один раз за попытку» запоминает показ до сброса; «После каждого действия» показывает каждое успешное событие. Ошибочные команды, повторные клики и кадры ничего не запускают. Событийная подсказка не соединяется с основной цепочкой выполнения и не продвигает её при подтверждении.

Подтверждаемая подсказка приостанавливает действия/обработку. Неподтверждаемая не останавливает цепочку. Сброс очищает очередь, сообщения и отметки показов; выход освобождает подписки.

## Карта и точки

Добавьте одну ноду «Карта»; её свойства показывают ширину, высоту и количество точек. Эти значения читаются из единственного `grid`, не копируются в параметры ноды. Количество равно числу реальных точек, не превышает площадь карты. Дополнительные точки выбираются построчно слева направо, сверху вниз. Уменьшение удаляет свободные точки с конца, сохраняя занятые. При уменьшении размеров свободные точки по возможности переносятся внутрь с сохранением ID; занятая точка за новой границей блокирует изменение.

Во вкладке карты выберите «Отмечать точки» для добавления/снятия свободных точек. «Перенести точку»: клик по свободной точке, затем по новой свободной клетке. ID сохраняется. Занятые точки нельзя удалить или перенести; сначала снимите объект или поставьте его на другую разрешённую точку. Точки отмечены цветом, занятые — зелёным. «Размещать объекты» ставит выбранный объект только на разрешённую свободную точку. Графическое положение ноды «Карта» ничего не меняет на площадке.

## Передача между этапами

Промежуточный склад имеет выход данных «Заготовка» → вход заготовки следующего станка. После помещения готовой детали выберите склад, нажмите **«Взять заготовку»**, затем выберите совместимый следующий станок. Отмена или неверная цель оставляют предмет в складе; удаление из инвентаря и установка выполняются атомарно только при успешном выборе. Конечный склад предметы не выдаёт. Вместимость учитывается отдельно на каждом складе, но физическая деталь одна.

Ожидание имеет дополнительный выход **«Деталь»** типа `actual-part`. Он становится доступен после фактического совпадения на нужном складе. До этого потребитель ждёт. Это ссылка на найденный предмет, а не копия требований. Явная совместимость `actual-part → blank` позволяет подключить ожидание к следующему станку. Выход можно также подключить к проверке выбора через «Фактическая деталь», включив «Проверять фактическую деталь» и подключив независимые требования. Подключение само по себе не переносит предмет.

Если склад и ожидание дают две ссылки, у них один ID предмета. После получения инвентарь склада пуст, ссылка завершённого ожидания по-прежнему указывает на тот же предмет с его текущей геометрией. Все операции на следующих станках сохраняют материал, ID, фактические размеры, участки и историю операций.

В примере «Два станка» второй станок добавляет **новый** участок Ø8 × 15 мм к прежнему Ø12 × 30 мм. Остаётся 15 мм исходного цилиндра Ø20. Он не обрабатывает заново первый участок. Для фрезерования следующая глубина проверяется по фактической оставшейся высоте. Невозможные конфигурации и превышение оставшейся длины отклоняются, даже если требования результата заданы другими числами.

Технические зависимости проверяются отдельно от выполнения: ожидание предыдущего этапа должно предшествовать потребителю на каждом пути; допустимая последовательная цепочка не считается циклом. Для промежуточного склада нужен однозначный производящий станок через ожидание. Несколько предметов, возврат к уже использованному станку и массовое производство не реализованы.


## План игрока: прохождение оси

Нажмите «Ось: план игрока», затем «Игрок» или «Протестировать». Задание и изображение с размерами показаны над каталогом. Панель «План производства» хранит выбор отдельно от авторского графа.

1. Выберите заготовку и станок. Тонкая стальная заготовка Ø10 физически не позволяет получить нужные участки; алюминиевая Ø20 позволяет обработку, но не соответствует требуемому материалу. Фрезерование плоскости работает с бруском, а заказ — цилиндрическая ось.
2. Выберите свободную точку на схеме или в списке. Стол и склад остаются на авторских точках. Смена станка или точки сохраняет операции.
3. Добавляйте только разрешённые операции. У каждой карточки собственный инструмент, размеры и кнопки ↑/↓/удаления. Назначения инструментов приведены рядом. Игрок не редактирует время.
4. «Проверить план» проверяет выполнимость последовательных операций. «Пробная обработка» показывает выбранный результат и размеры в области «После обработки», не создавая настоящего предмета, событий или инвентаря.
5. Рабочий пример: сталь Ø20 × 60, токарный станок, проходной резец; участок Ø12 × 20, затем Ø8 × 20. Также засчитывается разделение первого участка на два Ø12 × 10: итоговая геометрия та же, ID и время операций не являются условиями результата. Это пример для ручного прохождения, игра не подставляет его автоматически.
6. «Зафиксировать план и начать изготовление» создаёт одну исходную заготовку и один станок. Прочитайте вступление; далее установка → обработка каждой операции → готовая деталь → склад. Выбор объектов доступен и в цехе, и кнопками справа. Инструмент меняется автоматически по карточке операции. Изменение плана запрещено ядром до сдачи детали.
7. На складе сравниваются реальный материал, форма, размеры и профиль участков. Технически выполнимый ошибочный план можно изготовить. «Изменить план и попробовать снова» возвращает тот же черновик для исправления, очищая результат и склад; следующая попытка получает новую исходную заготовку. «Начать заново» очищает и план, отменяя текущую обработку.

## Авторский уровень с каталогом

Проще начать с примера оси. Для своего уровня выберите «План игрока» в поле «Режим производства». Создайте «Каталог» и обычные ноды определений заготовок, станков и инструментов. В свойствах каталога отметьте от 1 до 5 ссылок каждой категории и разрешённые операции; укажите положительную длительность каждой. Все определения этих категорий должны однозначно входить в каталог. Они не размещаются как физические объекты и могут быть неподходящими для заказа.

Добавьте «Полученную деталь» с независимыми требованиями и соедините Каталог → Полученная деталь → Ожидать деталь на складе. В ожидание подключите конечный склад. Сценарий: Начало → Вступление → Задание → Ожидание → Завершение. «Стол» и склад разместите на карте, оставьте минимум одну свободную разрешённую точку для выбранного станка. Готовую ноду «Техпроцесс» здесь не добавляют. Контекстные подсказки после установки/обработки/склада работают как прежде; фильтр может указывать вариант каталожного станка или любую успешную операцию.

В «Готовом плане» подключения и строгая проверка специальных заданий остаются прежними. Смена режима не удаляет ноды или связи автоматически: валидатор показывает, что нужно исправить. Исполнение свободного плана создаёт временный готовый маршрут и использует то же ядро, `operationCompatibility` и `applyOperation`, что и предпросмотр.

## Группы-рамки

Выделите несколько нод с Shift + кликами или правой кнопкой рамкой, затем «Группировать выделенные». Для новой группы нужны минимум две ещё не сгруппированные ноды. Выберите её заголовок и настройте имя/цвет справа. Перетаскивание заголовка перемещает всю группу; маркеры границ меняют только рамку. Ноду можно двигать внутри группы независимо. В свойствах ноды список «Группа» добавляет её в выбранную рамку или исключает из неё без изменения положения.

«Разгруппировать» и Delete/Backspace у выбранной рамки сохраняют ноды и связи. В JSON координаты групп и нод **абсолютные**; только адаптер редактора переводит детей в относительные координаты React Flow. Поэтому группировка/переназначение/разгруппировка не перемещают ноды, а общий сдвиг применяется один раз. Группы, цвет и размер сохраняются при экспорте/импорте/перезагрузке и не входят в скомпилированный сценарий.

Проверки нового этапа включают корректные и ошибочные попытки, два равнозначных маршрута, инструменты каждой операции, запрет изменений/повторных команд, чистый предпросмотр, сброс во время каждой операции, миграцию v3 и группы. UI-тесты jsdom отдельно проверяют исправление плана через реальные формы, порядок операций, создание/движение/изменение рамки, линии внутри и через границу группы и удаление рамки. Эти проверки не являются визуальным прохождением в настоящем браузере.

## Геометрия токарного обучения — этап 1

Подготовлен чистый программный API наружного/внутреннего профиля по Z, интервального точения, повторных проходов и подрезки свободного торца. На этапе 2 эта основа подключена к шести миссиям основной карты через отдельный учебный рабочий вид; универсальная форма новых операций в редакторе и изометрический цех пока не изменены. Формат старых уровней и фрезерование сохранены. Контракт для логики и оформления, миграция участков и ограничения: [TURNING_GEOMETRY.md](docs/TURNING_GEOMETRY.md); будущие этапы блока из 15 уровней — в [плане](docs/MVP.md#11-расширение-15-токарных-уровней).

## Школа точения: уровни 1–6

На основной карте доступны «Первая ступень», «Две ступени», «Три ступени», «Ровный торец», «Большой припуск» и «Гладкая поверхность». Включены безопасная проба X/Z, обороты, подача, глубина по радиусу, повторные проходы и качество последнего реального снятия. Подсказки и время размышления в этих учебных миссиях не штрафуются; олимпиады сохраняют прежнюю оценку. Реализация использует PlanningCore и FactoryCore. Размеры, учебные коэффициенты, настройки автора, ограничения и контракт оформления: [TURNING_TRAINING.md](docs/TURNING_TRAINING.md).

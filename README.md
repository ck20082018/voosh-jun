# Учебный завод: мастерская уровней

Локальный браузерный прототип для 5–7 классов: администратор проектирует уровень нодами, игрок проходит его в изометрическом цехе. TypeScript (strict), React, React Flow (`@xyflow/react`), Phaser и Vite. Все объекты созданы геометрическими примитивами Phaser. Без внешних изображений, сервера и регистрации.

Совместная работа: [инструкция для двух разработчиков](docs/COLLABORATION.md), [правила Codex](AGENTS.md).

## Запуск через Docker

Запустите Docker Desktop и выполните в папке проекта:

```sh
docker compose up --build -d
```

Откройте **http://localhost:8081**. Docker устанавливает зависимости, выполняет тесты и сборку, затем nginx раздаёт готовый сайт. Node.js на компьютере не нужен.

```sh
docker compose logs
# Остановить контейнер:
docker compose down
# Если порт 8081 занят:
DEMO_PORT=8090 docker compose up --build -d
```

После изменения кода повторите `docker compose up --build -d`. При разработке через Docker изменения исходников требуют пересборки; горячая перезагрузка доступна при локальном запуске Vite.

## Локальная разработка

Для разработки и тестов нужен Node.js 22.22.2+ в ветке 22, 24.15+ в ветке 24 или 26+. Docker уже использует подходящую версию.

```sh
npm ci
npm run dev
```

Откройте адрес Vite (обычно http://127.0.0.1:5173).

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

Сборка находится в `dist/`. Phaser выделяется Vite в общий модуль; его размер вызывает информационное предупреждение о большом чанке.

## Готовый пример и прохождение

При первом запуске открывается полностью подключённый и размещённый пример. Если в браузере сохранён корректный уровень, загружается он.

1. Нажмите «Протестировать» (с журналом администратора) или «Игрок» (без журнала).
2. Прочитайте вступление и нажмите «Начать».
3. Выберите заготовку на столе → «Установить в станок» → выберите станок.
4. На выбранном загруженном станке нажмите «Обработать» и дождитесь окончания.
5. Выберите готовый валик в станке → «Отправить на склад» → выберите склад.

«Отменить выбор цели» отменяет ожидаемый выбор станка/склада. «Начать заново» сбрасывает весь сценарий и обработку. Выход в редактор освобождает сцену и подписки. Игра приостанавливается в неактивной вкладке.

Кнопка «Пример»: сталь Ø20 × 60 мм, проходной резец, обработка до Ø12 мм на участке 30 мм за 3 секунды, склад на одну деталь. «Приветствие» загружает текстовый уровень без оборудования. «2 операции» загружает обработку двух участков: Ø12 × 30 мм за 3 секунды, затем Ø8 × 15 мм за 2 секунды.

Исходная простая демка сохранена и доступна по **http://localhost:8081/?demo=classic**. Её модель и тесты также сохранены отдельно.

## Создание уровня

- «Новый уровень» создаёт пустое описание; «Пример» восстанавливает готовый пример. Эти действия заменяют текущую несохранённую работу; сохраните/экспортируйте её заранее.
- Добавляйте ноды кнопками «+» в библиотеке, перетаскивайте их в граф или выберите тип в верхней панели и нажмите «+ Добавить ноду». Библиотека доступна и на вкладке карты; добавление переводит в граф. Новая нода получает свободное место и автоматически попадает в видимую область. Для уровня-приветствия нужны только начало, вступление и завершение. Оборудование требуется только при наличии производственного задания. Для производственного цикла нужны начало, задание, ожидание, завершение и по одной ноде заготовки, инструмента, станка и склада; операций может быть несколько. Вступления необязательны; их может быть несколько.
- Выберите ноду: размер меняется перетаскиванием маркеров по углам/краям или полями «Ширина ноды» и «Высота ноды» справа. Размер сохраняется в JSON отдельно от позиции и параметров. Измените её параметры справа. Тексты, размеры и время сразу обновляются в описании уровня.
- Перетаскивайте ноды за заголовки с маркером ⠿; связанные линии следуют за портами. Связь можно создать двумя кликами по подписям: сначала выход справа, затем совместимый вход слева. Свободные совместимые входы подсвечиваются. Также доступна кнопка «+ Добавить связь» в поле графа: выберите выход и вход в списках. Перетаскивание между увеличенными портами тоже работает. Если вход занят или типы несовместимы, показывается причина; для переподключения выберите старую линию и нажмите Delete/Backspace. Выберите ноду или связь и нажмите Delete/Backspace для удаления. Масштабируйте колесом или кнопками; перемещайте рабочее поле перетаскиванием пустого места. «Показать все ноды» возвращает весь граф в видимую область. Ноды и связи видны на вкладке «Граф сценария»; вкладка «Карта» показывает объекты цеха.
- На вкладке «Карта» выберите объект слева и нажмите свободную клетку. Размер сетки можно менять справа (до 8 × 8). Координаты ноды и координаты объекта независимы. При уменьшении сетки объекты за её границами нужно разместить заново.
- «Проверить» показывает ошибки и конкретные ноды; нажатие на ошибку выбирает её ноду. Некорректный уровень не запускается.
- «Сохранить» записывает уровень или незаконченный черновик в localStorage этого браузера. После перезагрузки можно продолжить работу. Некорректный черновик нельзя запустить. «Экспорт JSON» также позволяет сохранить незаконченный черновик. «Импорт JSON» принимает только полностью корректный уровень версии 1; при ошибке текущее описание остаётся без изменений.

Для проверки основного критерия измените текст ноды «Вступление», диаметр/длину участка и время в ноде «Операция точения». Запустите тест: вступление, прогресс, подпись размеров и форма готового валика будут соответствовать новым параметрам. Возврат из теста сохраняет описание редактора.

## Типы связей и нод

Золотые пунктирные связи — **выполнение**, голубые сплошные — **данные**. Оборудование не требуется для цепочки **начало → вступления → завершение**. Порты данных типизированы: заготовка, инструмент, операция, станок, склад. Несовместимые соединения и несколько связей в один вход запрещены при подключении и проверяются валидатором. Связи данных описывают ссылки; они не переносят предмет и не запускают станок.

| Нода | Назначение |
| --- | --- |
| Начало уровня | Единственная точка входа |
| Вступление | Заголовок/текст; ждёт кнопки «Начать» |
| Заготовка | Название, материал, диаметр и длина |
| Инструмент | Предустановленный проходной токарный резец |
| Операция точения | Заготовка, необязательная предыдущая операция, диаметр/длина участка и длительность |
| Токарный станок | Название, ссылки на инструмент и операцию |
| Склад | Название и целочисленная положительная вместимость |
| Задание | Цель/инструкция, ссылки на нужный станок и склад |
| Ожидать деталь на складе | Склад и операция с ожидаемыми характеристиками |
| Завершить уровень | Текст успеха и повторное прохождение |

Последовательность производственного уровня: **начало → задание → ожидание → завершение**. Между шагами можно добавлять вступления; каждое ждёт подтверждения игрока. Пример содержит одно вступление перед заданием. Задание активирует производство и передаёт выполнение ожиданию. Ожидание проверяет текущее состояние сразу при активации и затем слушает событие поступления детали. Завершение запускается ровно один раз.

## Архитектура

| Файл | Ответственность |
| --- | --- |
| `src/level.ts` | Формат уровня, реестр нод/портов/параметров, пример, операции размещения/удаления |
| `src/validation.ts` | Семантическая проверка графа, размеров и карты |
| `src/compiler.ts` | Преобразование подключённых нод в исполняемое описание |
| `src/core.ts` | Команды, единое состояние предмета, события и выполнение сценария |
| `src/storage.ts` | Проверка структуры JSON, сохранение/восстановление |
| `src/App.tsx` | Оболочка React, библиотека, свойства, панели игрока |
| `src/GraphEditor.tsx` | Редактор React Flow, ноды/порты, перетаскивание, связи и фокус добавленной ноды |
| `src/editorFlow.ts` | Согласование графа с моделью; сохранение полного состояния React Flow отдельно от уровня |
| `src/connections.ts`, `src/ConnectionBuilder.tsx` | Общие правила соединения и форма выбора выходов/входов |
| `src/Workshop.tsx` | Жизненный цикл Phaser, клики, команды ядра и передача снимка отрисовке |
| `src/presentation/workshopDrawing.ts` | Геометрия цеха, детали, подсветка и декоративная анимация; общая проекция клеток |
| `src/classic.ts`, `src/production.ts` | Сохранённая исходная демка |

Ядро и компилятор не импортируют React, Phaser, DOM или React Flow. Игровые кнопки используют `core.can`, а непосредственные вызовы команд повторно проверяют те же правила. На старте теста компилируется отдельная копия определения. Формат JSON содержит версию, ID/название, ноды/параметры, связи/порты, позиции, сетку и размещение; состояние прохождения в него не записывается.

Обработка считает время через `tick`, без отложенных таймеров. Сброс/выход отменяет обработку и очищает подписки, поэтому старый экземпляр не влияет на новый.

## Ограничения первой версии

В производственном уровне одна физическая заготовка, один станок, один предустановленный резец и один склад; последовательных операций может быть несколько. Текстовые уровни не требуют производственных объектов. Последовательный производственный цикл с произвольными ID и текстами, необязательными вступлениями и собственным размещением. Циклы, параллельные ветви, дубли физических объектов/обязательных шагов и неверный порядок производства показывают понятные ошибки при проверке. В редактор можно добавлять любые ноды и сохранять незаконченные черновики. Вместимость можно увеличить, но в уровне всё равно существует только одна деталь. Модель точения условная, без физики и расчёта сил; уменьшение диаметра и длина участка проверяются. Режимы администратора и игрока локальные, без разграничения доступа. Для комфортного редактирования графа рекомендуется настольный браузер.

## Добавление нового типа ноды

1. Добавьте тип в `NODE_TYPES` и определение в `registry`: название, параметры с начальными значениями, входные/выходные типизированные порты и правила параметров. Библиотека/панель свойств используют этот реестр автоматически.
2. Обновите правила количества и допустимой цепочки в `validation.ts` для выбранного расширения. Межобъектные проверки добавляйте там же.
3. Добавьте компиляцию ссылок/параметров в `compiler.ts`. Если это исполняемая нода, реализуйте её запуск/завершение в `FactoryCore.activate` и при необходимости событие.
4. Для размещаемого объекта добавьте разрешённый тип в операции карты/валидатор и отрисовку в `presentation/workshopDrawing.ts` и выбор в `Workshop.tsx`.
5. Добавьте тесты нового поведения и несовместимых соединений. При изменении структуры JSON измените версию формата и реализуйте явную миграцию.

## Проверки

Тесты покрывают полный цикл, запрет хранения необработанной заготовки, неверные цели и прямые запрещённые команды, повторные действия, нужные характеристики/склад, ожидание уже поступившей детали, параметры нод без изменения кода, сброс/выход во время обработки, очистку подписок, связи/циклы/порты, размеры, размещение/удаление и JSON/localStorage. Исходные три теста простой демки сохранены.

Тесты редактора проверяют сохранение размеров и данных перетаскивания, движение обоих концов связей для всех типов нод (включая начало уровня), создание полностью собственного уровня с новыми ID и прохождение. Тесты React-интерфейса в jsdom выполняют настоящие клики и события мыши: добавление в пустой проект, повторные добавления, движение SVG-линий при перетаскивании всех десяти типов и сохранение/восстановление черновика. Размеры и состояние редактора не попадают в JSON уровня. Эти проверки используют моделируемую геометрию DOM и не заменяют визуальную проверку в браузере.

## Несколько токарных операций

Быстрее всего нажать «2 операции» и изменить параметры готовой цепочки. Чтобы собрать её самостоятельно:

1. Добавьте несколько нод «Операция точения». Выход заготовки подключите ко входу «Заготовка» **каждой** операции.
2. Выход «Операция» первой ноды подключите ко входу «Предыдущая операция» второй. Аналогично соедините третью и следующие. У первой операции вход «Предыдущая операция» оставьте свободным.
3. Выход **последней** операции подключите к станку и к входу «Требования» ожидания детали на складе. Все остальные подключения задания, склада и инструмента остаются как в одном цикле.
4. В игре установите заготовку один раз. Нажимайте «Обработать 1 / N», затем «Обработать 2 / N» и далее. На склад можно отправить только результат всех операций.

Каждая операция обрабатывает следующий отдельный участок вдоль валика. Их суммарная длина не должна превышать длину заготовки; диаметры участков должны быть меньше исходного. Это несколько участков одной детали, а не повторные проходы резцом по одному участку. Форма готового валика показывает все участки. Сброс отменяет текущую операцию и очищает уже обработанные участки.

## Уровень-приветствие

Нажмите «Приветствие» или создайте начало, одно/несколько вступлений и завершение. Соедините их связями выполнения в нужном порядке. Измените тексты и запустите тест. Каждое вступление ждёт кнопки «Начать», затем переход к следующему тексту или итоговому сообщению. Стол, станок, инструмент, операция и склад для такого уровня не нужны.
